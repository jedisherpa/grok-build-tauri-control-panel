# Prism GT memory port and mathematical boundaries

Paul authorized a local Bomb Code port after asking about domain-guided clarification, progress questions and memory retrieval. Release 0.1.11 extends the existing Memory view and Joe reader. It does not add an agent runner or change coding approvals.

## Source and useful donor components

Donor: `jedisherpa/prism-geometry-talk`, `desktop/prism-gt-chat-live`, pinned commit `bd22d846130b2a255fa7eb83f3cf42bcb4e6b6a0`. `crates/prism-cdiss-cli/src/memory.rs` supplies the useful design of local Nomic embeddings, finite cosine ranking, compact float32 little-endian vectors and scoped notes. `knowledge_base.rs` supplies filtered lexical/vector retrieval, reciprocal-rank fusion and cited evidence. Bomb Code already owns native notes and imported transcripts, so this is an adapter around those stores rather than a second copy of their CRUD or execution services.

The donor's fabricated/hash-vector fallback, persona ranking boosts, cloud embedding fallback and dispatch paths are omitted. Missing local embeddings leave explicit lexical recall. Topic terms are literal user-selected filters; they are not a domain classifier. Saved-note scopes filter notes, not conversation permissions.

## Implemented retrieval and interpretation contract

1. Explicitly build a private, derived SQLite index from unchanged native notes and read-only imported history. Main-thread user and assistant passages get exact 1,000-Unicode-character chunks, whole-message and excerpt hashes, stable source IDs, timestamps, roles and half-open spans. Truncated sources, subagents, terminal output, credential-shaped strings and instruction wrappers remain excluded and counted.
2. Explicitly index local vectors using `nomic-embed-text:latest` on loopback Ollama. Pin its digest, dimension, `search_document:` / `search_query:` prefixes, no truncation, finite nonzero normalization and float32 storage basis. Each native call retains committed groups of eight and returns within a bounded time. The UI resumes batches of up to 128, can pause after the current batch, and stops on errors, changed model/index/basis, nondecreasing pending coverage or a finite batch cap.
3. Filter first; rank keywords with SQLite FTS5 BM25, local semantic vectors by cosine, then combine their ranks with RRF `1/(60+r)`. Keep ranks separate from confidence. Model-matched vector coverage is explicit; candidates beyond 50,000 semantic matches are visibly limited. Exact topic filters can exclude useful synonyms, so broad queries should be tested too.
4. Inspect and select one to eight citations. A bounded selected context is re-read from the original stores and verified before preparing an immutable native receipt. Joe receives the current question as its utterance and citations as separately typed context. This avoids turning a large archive excerpt into an unbounded atom inventory.
5. Only Analyze invokes the existing configured tool-free interpretation provider. Native source validation precedes the call, and validation occurs again before a result is shown or a question is drafted. Editing the input, changing selected citations, thread, intended outcome or source generation invalidates the prepared review. Drafting uses the original unsent composer.

The host supplies panel paths and notes; frontend requests cannot substitute arbitrary files or note bodies. Private directories/files use 0700/0600. The derived SQLite generation has a hard 1 GiB budget, including FTS and vectors; the separately reported serialized-text budget is 384 MiB. Writes require a 256 MiB disk reserve plus a 16 MiB allowance. Failed refreshes preserve the prior generation; failed vector groups roll back. Original stores are not deleted or migrated. History metadata cannot grant current permission; imported branch ordering remains unknown where parent links are absent.

## How the three mathematical representations cooperate

The learned 768-dimensional local vector retrieves candidate passages. Its cosine score is useful for ranking, subject to independent relevance review. The sparse CDISS identity/event measures retain proposed senses, ambiguity, roles, negation, modality and references. TV and square-root base-2 Jensen–Shannon describe changes in compatible identity distributions. Native E8 and SenseSnap coordinates remain unchanged source descriptors for the interpretation that was actually bound. None of these is a probability of user intention, permission, truth or completion.

This release does not project semantic embeddings onto E8 roots, blend incompatible distances, manufacture missing sense geometry, or use low CDISS distance as a relevance/acceptance label. Selected topic/evidence is included in the pinned interpretation context, so context changes reset incompatible continuity comparisons. Domain-specific sense references and contextual pins should be evaluated on their own provenance before becoming additional retrieval channels.

## Research and observed evidence

Passage-grounded mixed-initiative clarification has a research basis: [DialDoc 2022](https://aclanthology.org/2022.dialdoc-1.7/) studies choosing clarification questions with passage retrieval. [LongMemEval](https://arxiv.org/abs/2410.10813) evaluates extraction, cross-session, temporal, updated-memory and abstention tasks. These support separate retrieval and reading stages and an evaluation design, not accuracy claims for this app. [Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/) reports position-sensitive long-context performance, supporting bounded inspectable evidence rather than an archive dump.

The ranking baseline follows [RRF's original paper](https://cormack.uwaterloo.ca/cormack/cormacksigir09-rrf.pdf), and lower BM25 scores sort first per [SQLite FTS5](https://www.sqlite.org/fts5.html). Local calls follow [Ollama's embed contract](https://docs.ollama.com/api/embed) and Nomic's required prefixes in its [official model card](https://huggingface.co/nomic-ai/nomic-embed-text-v1.5). Model-specific vectors require a shared pinned basis; geometric coordinates are a different representation.

The actual read-only history library contains 1,608 threads and 42,195 message rows. The first port indexed 29,755 chunks from 20,641 eligible user/assistant messages: 179 ChatGPT, 973 Claude Code, 18,592 Codex and 897 Grok; there were zero native saved notes. Exclusions were 13,710 subagent messages, 7,327 terminal messages, 508 instruction wrappers, five credential-shaped messages and four truncated messages. Coverage reflects the actual stored/imported material, not all past accounts or all thread branches. The first 128 real local vectors succeeded at 768 dimensions; the later compact-storage full-index receipt is recorded separately in private release evidence.

The independent history experiment selected 48 actual passages; 28 bound and replayed with unchanged source candidate sets and native geometry, and 20 remained whole-case budget failures. Its literal no-lemma inventory had sparse exact-form dictionary grounding and deliberately empty event frames. It cannot qualify linguistic accuracy, contextual pins, role detection or progress. See [HISTORY_BENCHMARK.md](HISTORY_BENCHMARK.md) for the boundaries and preservation checks.

Two installed 0.1.10 live Joe probes used harmless complete historical wording. One returned a useful clarification proposal concerning an antecedent, an implicit comparison and literal/figurative cloud meaning, despite unavailable fitted geometry. The other failed structured-outline validation after one repair and remained unavailable. These are observed examples, with no human gold labels; they are not two successful trials.

## Next evaluations and progress support

Paul can judge recall with paired queries and relevant/irrelevant source IDs: compare lexical-only, semantic-only and fused top-k; record source recall, stale-citation rejection, domain filter losses, negation/role-sensitive cases, chronology, corrections and abstention. Keep evaluation passages and judgments private. A useful initial gate is a fixed 30-question set across several domains, judged before adjusting weights; compare recall@5/10 and clarification usefulness against the existing reader. Synthetic ranking tests establish mechanics only.

Questions along a path toward completion should use an explicit human-approved goal, unresolved questions, evidence of answer/decision, dependencies and acceptance criteria. Existing reviewed Builds already records six checkpoints. Ordinary sessions and imported archives retain unknown completion unless those records exist. A future domain/workflow question planner can propose the next unresolved question from selected evidence; it must not derive general percent complete from message volume, embeddings or CDISS proximity.

Entity graphs/community summaries may help cross-archive theme questions later; [GraphRAG](https://arxiv.org/abs/2404.16130) is a research direction requiring separate cost and quality evaluation. The present cited hybrid search is the smaller port with a testable source contract.
