# Full-chain retrieval and clarification experiment

Paul clarified that the computational word-definition → meaning → sense →
context/use → E8 chain is the resource to exploit. The viewer is an interface.
This experiment therefore compares the complete retained representation instead
of the earlier definition-expansion, cue and mean-vector proxies.

Implemented in the isolated `codex/full-chain-retrieval` research branch:

- A pure native `grok_cdiss::retrieval` API accepts original internally validated
  Joe proposals. Profiles retain every reading, occurrence, source alternative,
  selected definition/alignment, complete SenseSnap center, event frame and
  unchanged activation. Typed asserted-equivalent concept postings allow direct
  cross-language lookup without parsing composite identifiers or clipping aliases.
- Separate source-sense, asserted-concept, dictionary-center, scoped-context and
  predicate-local event distributions use total variation and square-root
  base-2 Jensen–Shannon distances. Full frames, links, references, repeated
  occurrences and uncertainty accompany the calculations. There is no weighted
  overall relevance score or averaging away of event membership.
- Coarse root postings retain fine positions, source identity and residuals.
  Matching roots can locate a candidate bucket; fine-coordinate differences are
  separately available for comparison.
- A read-only archive adapter enumerates all asserted source-equivalent forms
  within explicit whole-result budgets. Lexical hits retain all same-form sense
  alternatives as UNSELECTED, original Unicode spans and validated citations.
- A deterministic helper prepares unsent questions from competing source senses,
  event participant/scope differences, references, links and contextual pins.
  Questions carry original reading/event/occurrence references. Ambiguous repeated
  predicate correspondences do not invent an event match.

## Actual archive and saved proposal checks

The final source-concept query scanned **29,755 indexed chunks**, enumerating ten

**9.50 seconds**. All usages remain unselected. Source/index/reference hashes

passages. The adapter's six-concept bilingual tests include both Japanese forms
excluded by the earlier twelve-alias cap.

All seven original saved Joe receipts were replayed without provider calls.
The **five successful proposals retained all 14 readings** and complete profiles;
the two earlier failed proposals remained unavailable. Every original receipt

The archive has no structured interpretation profiles for all 29,755 chunks.

verified interpreted packets. End-to-end relevance improvement over the existing
hybrid search remains unmeasured for this implementation.

## Practical integration

1. Keep existing keyword/vector candidate retrieval. Add this source-concept
   channel to recover source-linked forms that exact keywords miss, respecting
   existing provider/date/topic filters and original citation validation.
2. Store immutable interpreted profiles beside their existing citations when
   the user explicitly analyzes a passage. Key validity to the exact excerpt,
   reference graph/model, native implementation and declared context. Invalidate
   stale joins through the existing host controls.
3. Compare the interpreted query with available candidate profiles. Show separate
   evidence for shared concept, selected sense, context, event relations and fine
   geometry in an explain-match card. Same words with changed actors or scope can
   be surfaced explicitly. Annotate unprocessed candidates only through the
   existing manual Joe provider flow.
4. Use disagreements to prepare source-linked clarification choices. Feed these
   structured components and citations into the existing LLM handoff when the user
   requests synthesis. Retain all competing readings until the user resolves them.
5. Freeze independent domain relevance/hard-negative labels before evaluating a
   new ordering. Evaluate candidate recall, wrong-sense false matches and question
   usefulness separately. Domain selection can use the existing topic/context
   input; a domain-specific learned model is not implemented by these controls.

The local prototype and question drafts are implemented and tested. They are not
yet connected to the installed Memory UI or activated as its ranking policy.
The installed app/primary source remains the existing 0.1.12 baseline.

## Verification and preserved failures

The first full run found default JSON float parsing changed several coordinates
by one IEEE unit. Its output is retained. Enabling `serde_json`'s existing
`float_roundtrip` feature corrected parsing; a new exact-bit regression covers
real source coordinates, negatives and a subnormal. The final run uses binary SHA
`493cf4097b1d7d2deec6adafd5af4d766fc87c7e8e7cd4b732276000e169741e`;
its input/output source records and coordinates passed exact equality, without
numeric tolerance. No dictionary/model changes or coordinate refitting occurred.

Architecture and performance reviews resolved source-center proof, unresolved
selected-sense retention, repeated identity diagnostics, proof/posting allocation,
index size/text budgets, per-occurrence concept counts and question-loop bounds.
No unresolved Critical, High or actionable Medium findings remain.

Final verification: **195 Rust workspace tests passed**, zero failed, two existing
real-dev-server fixtures ignored. Workspace check and strict all-target Clippy
passed. Source candidate tests **15/15**, authored generator tests **4/4**, and
clarification/harness tests **4/4** passed. Full-chain actual packets/receipts were
then checked independently of these unit tests. No frontend was changed; no
provider, embedding, archive/index write, app installation or remote publication
occurred. Private raw examples and result receipts remain outside Git.
