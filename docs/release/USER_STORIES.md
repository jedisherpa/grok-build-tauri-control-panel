Revision 2, 2026-10-07. These expectations are derived from the current Tauri commands and visible controls, not from passing tests. Every row requires both its stated automatic coverage and the packaged workflow described here. Existing historical evidence is useful context but does not qualify the new candidate. `QUALIFICATION_REPORT.md` records the current evidence and open gates.

A story passes only when its observable outcome and failure case hold on the pinned candidate. If an expectation is wrong, record the original expectation, product rationale, revised expectation, new test and rerun in `STORY_REVISIONS.md`. Do not weaken an authority or data-preservation rule to match an implementation defect.

## Evidence levels

`automatic` = pure/native unit and fixture suites; `packaged` = exact bundle running end to end; `provider` = actual configured backend with authored input; `recovery` = deliberate owned-process interruption; `external` = clean Mac, Haven service, Apple and download qualification. Stories can have partial evidence but cannot be marked passed on a weaker level than required.
