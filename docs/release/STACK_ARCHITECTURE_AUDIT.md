# Rust/Tauri stack architecture audit

Audit date: 2026-10-07. Source baseline: `baa890860d7f6b703757e62f9b58b33a7fe82648`; lane `codex/c3-release-qualification`. This audit covers the current Rust/Tauri product, not a GPUI migration. Root-owned qualification edits were in progress during initial inspection. A focused independent re-review of the final source repairs and named regression receipts was completed on 2026-10-07; baseline defects, source fixes and outstanding packaged gates are separated below. This report is the only repository file owned by this audit lane.

## Assessment

Keep the existing Tauri host, ACP SessionRegistry, reviewed BuildService, pure workflow/CDISS crates and source-backed meaning/memory contracts. The highest-value simplification is eliminating inconsistent ownership of policy, process completion, repository mutation and durable state. Removing distinctive math or replacing the desktop renderer does not repair these failures.

The source remains unqualified for production. Concrete baseline fixture reproductions establish permission inconsistencies, false scheduler completion/history loss, concurrent note publication errors, lossy event transport and inaccurate diff capture. The note publication race, corrupt-configuration overwrite, corruption-backup overwrite and Unicode clipping panics are now repaired at source with passing regression evidence; permission, scheduler, event and diff findings remain open. Current source inspection alone does not establish final packaged behavior, signing, notarization, provider compatibility or human usefulness.

## What changed since the teardown

- Main now has C3 studio, lattice panels, play surface, tour start and numbered dependent build submission. This is Tauri delivery of design work; it does not implement the proposed single host journal/supervisor/authority/memory facade.
- Scheduler now has UI controls, increasing the importance of A04/A05; the old finding that it had no frontend caller is outdated.
- Existing notes/history/hybrid recall/source concepts/profile comparisons/CDISS/E8 remain present. They are distinct data or computation contracts, not unnecessary duplicate stores.
- Native MCP compatibility commands already delegate to McpManager (`commands.rs:1706–1753`); duplicate extension-service internal methods remain (`grok_extensions/src/lib.rs:100–204`) with no current production caller found. Remove internal duplicate implementation only after caller/data/CLI-mirror parity checks; retain compatibility commands and skills/plugin records.
- Reviewed SemanticRuntime removes user-specific Node/Python/reference constants in Joe and word-shape workers; Python dictionary/source-candidate defaults now use `Path.home()`. Its another-user/spaces regression passes. Source-candidate host still injects the isolated panel explicitly through `run_host`, while frozen dictionary root remains actual-home and validated. PATH Node selection checks only file presence, not immutable runtime version/hash or license; provisioned dependency verification and clean-machine smoke remain open.
- Configuration, Unicode, same-instance note publication and corrupt-note preservation now have passing source regressions. Existing production files were not changed by these generated fixtures. Original adverse receipts are retained as baseline evidence; do not rerun their expects-defect note test against repaired code and call its failure a new regression.

Same-instance note serialization is implemented; cross-process and power-loss behavior remain separate gates. Do not change schemas/path identities or rebrand data stores at the same time.

3. Add common workspace admission to plain sessions/Builds/Land/Sync/remove; reject failed requested isolation and require reviewed checkpoint scope. Preserve conflict behavior and exact before/after OIDs.
4. Make transcript persistence reliable before UI completeness claims: owned durable ingress/journal and replay/resync; explicit per-thread coverage if admission fails. A new whole-product outbox is not required to hide a current gap; implement a narrow receipt contract and fault-inject it first.
5. Unify worker envelope and correct diff/capture contracts, then remove proven internal duplication. Keep existing memory files and frozen math unchanged. Measure resource/startup/scrolling with representative scenes after correctness fixes.
6. Complete all required stories against exact native bundle and source/artifact receipt. Compare before/after protected-store hashes. Only then move to Developer ID candidate and notarized download qualification. Unit passes and codesign alone cannot close these gates.
